# 30 дней

Публичный календарь челленджа: статья в день с конспектом и рисунок в день.
Сайт собирается из файлов в `entries/` и публикуется на GitHub Pages.

## Правила

- **Тридцать дней**, даты задаются в `config.json` (`start` и `days`).
- **День кончается в 02:00 по UTC+5**, а не в полночь. Запись, сделанная в час ночи,
  засчитывается за прошедший день.
- **Пропуски не обнуляют счёт.** Они просто остаются видны в календаре — этого достаточно.
- **Сколько угодно записей в день.** Две статьи и три рисунка за день — нормально.
  В календаре такой день помечается раздвоенным штрихом, в сводке считаются сами
  записи, а не дни.

## Как добавить запись

### С телефона — через issue (основной способ)

1. Открыть репозиторий → **Issues** → **New issue**.
2. Выбрать «Статья за день» или «Рисунок за день».
3. Заполнить поля. Картинку перетащить прямо в поле «Рисунок» — сжимать не нужно.
4. Отправить. Дальше всё само: запись сохранится в `entries/`, issue закроется
   с подтверждением, сайт пересоберётся за минуту.

Если что-то заполнено неверно, бот напишет об этом комментарием. Отредактируй issue —
он попробует снова: правка находит свою запись по номеру issue и меняет именно её.

Хочешь вторую статью за тот же день — просто заведи ещё один issue. Он ляжет
рядом отдельной записью, ничего не затирая.

Issue от кого угодно, кроме владельца репозитория, игнорируются: комментировать могут все,
писать в дневник — только я.

### С компьютера — через файлы

```bash
node scripts/new.mjs reading
node scripts/new.mjs drawing --image "C:/путь/к/рисунку.png"
```

Скрипт сам берёт следующее свободное место за этот день, так что повторный запуск
создаёт вторую запись, а не ругается. Заполнить, затем:

```bash
git add -A && git commit -m "день 5" && git push
```

Задним числом: `--date 2026-09-14`.

## Как посмотреть локально

```bash
node scripts/build.mjs                  # собрать в dist/
python -m http.server 8099 -d dist      # открыть http://127.0.0.1:8099
```

Посмотреть на демо-данных, не трогая реальные записи:

```bash
node scripts/demo.mjs
CONFIG_FILE=.demo/config.json ENTRIES_DIR=.demo/entries OUT_DIR=.demo/dist node scripts/build.mjs
```

## Структура

```
config.json              настройки челленджа: даты, часовой пояс, привычки
entries/ГГГГ-ММ-ДД/      записи за день
  reading.md             конспект + ссылка/автор/источник во фронтматтере
  reading-2.md           вторая статья за тот же день (и так далее)
  drawing.md             комментарий к рисунку
  drawing.png            сам рисунок в исходном размере
  drawing-2.md           второй рисунок за день
  drawing-2.png          и его картинка — имя файла совпадает с записью
site/style.css           стили сайта
scripts/build.mjs        сборка статики в dist/
scripts/ingest.mjs       issue → запись (запускается из Actions)
scripts/new.mjs          заготовка записи с компьютера
scripts/demo.mjs         демо-наполнение для превью
scripts/lib/             разбор markdown и работа с датами
```

Зависимостей нет — только Node 20+. `npm install` не нужен.

## Формат записи

```markdown
---
habit: reading
date: 2026-09-13
title: Название статьи
url: https://example.com/article
author: Имя автора
source: Где опубликовано
minutes: 15
---

Конспект в markdown.
```

Для рисунка вместо `url`/`author` — `image` (имя файла рядом), `tool` и `minutes`.
Поле `issue` проставляется автоматически и связывает запись с исходным issue,
чтобы правка issue меняла свою запись, а не создавала новую.

Про авторские права: в конспекте хранится только ссылка, название, автор и мой
пересказ своими словами. Полные тексты чужих статей сюда не копируются.

## Настройка после клонирования

1. `config.json` → `start` (дата старта), `owner`, `repo`, тексты в `title`/`about`.
2. Settings → Pages → Source: **GitHub Actions**.
3. Первый деплой: вкладка Actions → «Собрать и опубликовать» → Run workflow.

Календарь пересобирается сам раз в сутки, чтобы вчерашние пропуски проявлялись
без ручного вмешательства.
